## 1. まず作るもの

小学生が、普段の会話では出会いにくい言葉や知識に触れる任意の遊び。「勉強を管理する」より「相棒と遊んだら、ひとつ知った」を目指す。

- 「ことば」「えいご」「ふしぎ」から本人が選ぶ。1セットは同じジャンルの3問、選択式。
- 宿題が終わっていなくても開始できる。途中でやめられ、やらない日を未完了・遅れ・親への例外通知にしない。
- 正解数ではなく、3問に応答し、各問の解説画面から進んだ行動にポイントを付ける。「わからない」も有効な応答。
- 加点は子ごとに1日1セットまで、全ジャンル共通。もっと遊ぶことはできるが追加ポイントはない。
- 問題・正解・基本解説は確認済みデータ。生成APIは回答後の短い例え・対話を担当する。
- 相棒の名前・げんきタイプ・テーマ3つ・学年別表記・親も会話を見られる方針は [UX_SPEC.md](../UX_SPEC.md) を引き継ぐ。

配点は親が決める。提案は **1セット1pt**。これは承認済みの既存配点ではない。親が明示的に設定するまで加点を有効にせず、開始前に「いまはポイントなしであそべるよ」と表示する。設定UIは実装時に既存の親設定へ統合し、別の管理画面を増やさない。

### 今回の決定と保留

| 区分 | 内容 |
|---|---|
| 会話で合意した方向 | 小学生、3ジャンル、3問、宿題とは独立、参加への報酬、確認済み問題＋API対話 |
| この案で具体化した提案 | 1pt、わからないでも参加成立、1日単位、1セット全体で追加対話は2往復まで |

## 2. 画面の流れ

```text
/kid「クイズであそぶ」
  → ジャンルを選ぶ（3問・ポイント条件を表示）
  → 問題 → 選ぶ／わからない → 正解と短い解説 → つぎへ
       ↑ この流れを3問。回答後だけ任意の「相棒とはなす」
  → 完了・加点結果 →「今日にもどる」／「もっとあそぶ」
```

入口は `/kid` の相棒領域の副操作。最初のタスク、既存の「はなす」「声で話す」を押しのけず、下部ナビは「今日・撮る・ごほうび」の3つを維持。クイズは第4タブにせず、専用の子画面へ遷移する想定（候補 `/quiz`、ルート確定は実装計画時）。

| 画面 | 内容・操作 | 文言例 |
|---|---|---|
| ジャンル | ことば／えいご／ふしぎ、戻る。各ジャンルのボタンから直接3問を開始 | 「どれであそぶ？」、設定済みなら「3もんで1セット。解説まで見ると1pt・1日1回」 |
| 問題 | 問題文、読み上げ、縦3択、「わからない」、閉じる。進捗は画面だけに「1/3」 | 「ことばであそぼう」 |
| 回答後 | 選んだ答えと正解を区別。正解・解説は固定データ。つぎへを主操作、相棒との対話は任意 | 「こたえは『一石二鳥』」、誤答時も赤い×・失敗音を使わない |
| 完了 | 点数・正答率は出さない。記録が確定した場合だけ獲得ptを表示 | 「ひとつ、知るあそびをしたね！」、画面に「クイズに取り組んだ ＋1pt」 |
| 加点済みの再訪 | 新しいセットを始める前から追加加点がないことを明示 | 「今日のポイントは受け取りずみ。つづけてあそべるよ」 |

選択後に自動で次問へ飛ばさない。正解までの選び直しを要求しない。誤タップでも学習が続くため、正誤の訂正はポイントに影響しない。解説画面の「つぎへ」、最終問の「おわる」で閲覧ステップを記録する。理解・読了そのものを監視できるとは主張しない。最低滞在時間や視線・写真による証明を要求しない。

途中離脱時は「ここまでを残して、今日にもどる」。次の訪問では「つづきから／はじめから」。途中の問題は宿題一覧に入れず、続きの通知・バッジは付けない。はじめからを選んでも途中セットに加点しない。

### 見た目・表記・音

- ロボット・モノクロ・しろい小鳥をそのまま使う。クイズ用の新キャラ、背景生成、テーマ追加はしない。
- タップ領域48px以上、文字200%・320px幅・明暗対応。色だけで選択／正解を伝えない。相棒や動きがなくても進行できる。
- 学年別の漢字・ふりがなを適用する。ことわざ・四字熟語は学習対象として漢字を残し、語単位の読みを添える。今回は意味を知る遊びなので読みを隠さない。
- 上の子が開いても漢字をひらがなへ一律変換しない。テーマから難易度を推測しない。中学生用カリキュラムは作らない。
- 英語は音と意味の対応を中心にする。録音や発音採点は要求しない。問題ごとに確認済みの音声を用意するのが公開条件。辞書サイトの音声を無断で複製しない。
- 音声は本人の再生操作から開始し、何度でも聞ける。英語を日本語音声で読ませない。テキスト表示も選べ、聞こえない環境や聴覚に困難があっても同じ参加ポイントを得られる。
- 選択肢は文字ラベルを必ず持つ。絵や色は補助にとどめ、画像がなくても成立させる。

## 3. 相棒とAPIの役割

### 「答えを言わない」との境界

通常の `kid_agent` に「何でも答えてよい」という例外を足さない。宿題・写真の問題・子が持ち込んだ自由問題は従来どおり、場所とやり方のヒントまで。

アプリ内で承認済みの問題を出すクイズでは、本人の回答／「わからない」の後に、専用カードが正解と解説を表示する。これは採点・解説機能の限定追加として、実装時に画面設計と要件の整合を人が確認する。LLMによる採点や、未回答の答えの生成はしない。

API対話は解説表示後だけ。公開済みの説明を身近な場面に結び付ける。表示済みの正解を言い換えることはできるが、他の未回答問題の正解・外部の宿題の答えを渡さない。別問題を自由に持ち込んだ場合はクイズ解説の対象外として通常の伴走ルールに戻る。

### 会話の長さ

固定の出題・解説は自由雑談ではなく、本人が開始した3問の活動。APIによる追加対話は **1セット合計2往復まで**（子の発話1回＋相棒1回で1往復）。問を変えてもカウントをリセットしない。使い切ったら「つづきは、クイズのあとにしよう。いまの画面にもどるね」で対話を閉じ、未完了なら解説へ、完了なら今日への出口を示す。今日のタスクを強制開始しない。

この「クイズ中は活動へ戻す」点は既存の雑談2往復ルールに対する限定的な文脈整理であり、通常会話の制限解除ではない。セットの終わりに自動で自由会話へ移らない。もっと遊ぶ選択は残すが、次セットを自動開始しない。

| 場面 | 相棒の例 | 避けるもの |
|---|---|---|
| 開始 | 「ことば・えいご・ふしぎ、どれであそぶ？」 | 宿題を終えた子だけ誘う |
| 迷う | 「『わからない』から、いっしょに見てもいいよ」 | 未回答の正解をほのめかす |
| 解説の後 | 「このことば、どんなときに使えそう？」 | 「かんたんだったね」「覚えた？」 |
| 一石二鳥の説明後に「ゲームでもある？」 | 「あるね！ 探検しながら材料も集められたら、そんな場面だね」 | 特定ゲームの未確認の仕様を断定する |
| 「わからない」ばかりだった | 「いろんなことばに出会ったね。今日はここまでにする？」 | 正答率、能力の評価、減点 |
| 途中でやめる | 「うん、ここまでにしよう！」 | 「あと2問だけ」「せっかく始めたのに」 |
| 加点成功 | 「クイズの記録がついたよ！」 | 残りptの読み上げ、保存前の獲得宣言 |
| APIが不明な話題に出会う | 「それは、今はたしかめられないな」 | もっともらしい豆知識の捏造 |

### 生成APIへの制約

入力はサーバーで確定した問題ID・版・回答後状態・承認済み解説、学年表記方針、相棒名、当該セットの短い会話だけ。学校名、実名、他の子の履歴、写真、全タスクを送らない。趣味は本人が今話した内容だけを使い、広告用や長期の興味プロフィールに蓄積しない。

モデルは人格の評価・残数の発話・叱責・秘密の約束をしない。知識の追加は承認済みの根拠範囲にとどめ、例えは例えだと分かる形にする。新しい事実・出典・発音記号を作らない。HTMLや操作命令ではなく短い平文を返す。子の発話を設定変更命令として扱わず、台帳・採点・宿題完了・交換のツールを与えない。

API失敗時も、固定の問題・解説と加点処理は独立して続けられる。「いまは返事がつながらないよ。クイズはつづけられるよ」を表示。常時ストリーミング・問題ごとの自動生成は使わない。要求があったときだけ1往復1リクエスト、セット上限2、同一送信の再送は重複生成しない。家庭単位の日次生成上限をサーバー設定として持ち、上限時は固定文で継続。上限値は運用予算を見て実装時に設定するが、上限未設定では生成を有効化しない。

マイクは会話の任意入力であり、回答判定には使わない。許可拒否・認識失敗でも文字入力へ進める。新しい録音保存は追加せず、変換した会話には「おうちの人も見られます」を常時表示。クイズ会話も既存と同じ親閲覧・削除方針へ接続できるまで公開しない。

## 4. ポイントと記録

| 条件 | 仕様 |
|---|---|
| 参加成立 | サーバーで発行した3問すべてに選択または「わからない」を記録し、各問の解説画面から進んだこと。正誤・再生時間・会話利用は条件外 |
| 配点 | 親が承認・設定した固定値。案は1pt。既存の宿題3pt等を変更しない |
| 日の境界 | この家庭の初期設定はAsia/Tokyo。サーバーの完了確定時の家庭日付を使い、端末時計は信用しない |
| 上限 | 家庭ID＋子ID＋家庭日付で加点1回。ジャンル・セット・端末を変えても共通 |
| 台帳 | 専用reason候補 `quiz_participation`、表示「クイズに取り組んだ」。宿題やテスト直しとして偽装しない |
| 二重送信 | 完了記録と加点権の確定と台帳追加を原子的に扱う。同じセットIDの再送は同じ結果を返す |
| 日またぎ | 途中セットは再開でき、完了した日に判定する。一度完了したセットの翌日再送で新たな加点をしない |
| 設定変更 | 開始時に配点・有効状態の版を固定。親の変更は次に始めるセットから適用。過去の記録を巻き戻さない |
| 演出 | サーバー確定後に小さなチェックと獲得pt。再訪・同一応答の再表示で祝賀を繰り返さない。動き低減設定に従う |

毎日の宿題台紙・週次タスク目標には加算しない。クイズの完了をタスク1件の完了に置換するとPRODUCTの成功指標を満たしたように見えてしまうため、別の活動記録とする。兄弟比較や正答率一覧を親の一覧へ追加しない。

## 5. 空・誤答・途中・エラー

| 状態 | 見せ方と回復 |
|---|---|
| 誤答／わからない | 正解・短い理由を同じ強さで提示。参加扱いは変えず、やり直しを強制しない |
| そのジャンルに確認済み問題が3問未満 | 「このあそびは準備中だよ」＋別ジャンルへ。未確認のAI生成で穴埋めしない |
| 全問既出 | 「前に出会った問題でもあそべるよ」。既出は不利益にせず、同日加点は増やさない |
| 途中離脱 | 確認済み進捗を残す。中断を叱らず、加点は未成立。再訪時に続きか新規を選ぶ |
| 通信断 | その問題と解説が表示可能なら閲覧できるが、未送信は「まだ記録できていないよ」。再接続後に同一セットを照合。初版は完全オフラインでの新規開始をしない |
| 完了送信の応答不明 | 「記録をたしかめています」。ptを先に増やさず、同じ要求IDで照会・再試行。完了済みなら同じ結果を返す |
| 英語音声が再生できない | 「音が出ないときは、文字でもあそべるよ」。単語テキストを表示し、音声回答必須にしない |
| 会話API失敗／予算上限 | 固定問題・解説は継続。AI待ちで次問やポイントを止めない |
| 子の切替 | セットを子ごとに分離。古い子の通信応答・ポイント演出・会話を新しい子に表示しない |
| 誤った問題が後で見つかった | 新規出題を停止し、開いているセットでは理由を表示して代替問題へ。完了済みの参加ptを取り消さない |

## 6. サンプル問題9問

以下は独自に書いたレビュー用原稿。意味・事実の根拠を確認したが、子どもの試用・英語音声の制作と試聴・公開校閲は未実施。現時点では `draft` とし、実装へそのまま公開データとして投入しない。掲載順は確認用であり、正解位置に偏りがある場合はセット生成時に調整し、セット中は順番を固定する。

原稿の括弧内は読みの指定。実画面では学年設定に応じてrubyを使う。ことばの学習対象の読みは常に参照可能にする。出典は親向け詳細に置き、子の回答途中で外部サイトへ遷移させない。

### ことば：身近な場面から

#### K01 一石二鳥（いっせきにちょう）／四字熟語

- 問題：「犬のさんぽで、じぶんの運動もできたよ。ひとつのことで、ふたついいことがあった。どのことばかな？」
- 選択肢：A 一石二鳥（いっせきにちょう）／B 十人十色（じゅうにんといろ）／C 猿も木から落ちる（さるもきからおちる）
- 正解：A。
- 固定解説：「ひとつのことをして、ふたつのよい結果があることを『一石二鳥』というよ。」
- 日常の例：「歩いて図書館に行って、本も借りられたし運動にもなった！」
- 任意の対話起点：「遊んでいるときにも、こんなことはあるかな？」
- 根拠：[漢字ペディア「一石二鳥」](https://www.kanjipedia.jp/kotoba/0000233400)。語源の狩猟を遊びとして実演・推奨しない。

#### K02 猿も木から落ちる（さるもきからおちる）／ことわざ

- 問題：「『猿も木から落ちる』は、どんなことを表すことばかな？」
- 選択肢：A 木に登ると空を飛べる／B 得意な人でも失敗することがある／C 猿はみんな木登りが苦手
- 正解：B。
- 固定解説：「得意なことでも、うまくいかないときがある、という意味だよ。」
- 日常の例：「折り紙が得意な人も、折る向きをまちがえることがあるね。」
- 任意の対話起点：「ことばの意味を、別の遊びにたとえてみる？」
- 根拠：[漢字ペディア「猿も木から落ちる」](https://www.kanjipedia.jp/kotoba/0000468700)。子の失敗をこのことわざで評したり、失敗経験の告白を求めたりしない。

#### K03 十人十色（じゅうにんといろ）／四字熟語

- 問題：「友だちは電車が好き。ぼくは虫が好き。好きなものや考えは、人によってちがうね。どのことばかな？」
- 選択肢：A 一石二鳥（いっせきにちょう）／B 猿も木から落ちる（さるもきからおちる）／C 十人十色（じゅうにんといろ）
- 正解：C。
- 固定解説：「人によって、好きなものや考え方がちがうことを『十人十色』というよ。ちょうど十人のときだけではないんだ。」
- 日常の例：「好きな相棒の見た目がちがうのも、十人十色だね。」
- 任意の対話起点：「今、気に入っている見た目のどこが好き？」
- 根拠：[漢字ペディア「十人十色」](https://www.kanjipedia.jp/kotoba/0003163200)。兄弟の好みや能力を順位付けしない。

### えいご：音と知っているものを結ぶ

3問共通：音声を再生するボタンと「文字でも見る」を提供。初回自動再生はしない。正解後は英単語の文字・意味・再生ボタンを並べる。発音用のカタカナ表記を唯一の音の見本にしない。

#### E01 apple／食べ物

- 問題：「音を聞いてね。どの食べ物かな？」。音声原稿：`apple`。
- 選択肢：A バナナ／B りんご／C ぶどう。絵を付ける場合もこの文字ラベルを残す。
- 正解：B。
- 固定解説：「apple は、りんごのことだよ。」
- 日常の例：「おやつにりんごが出たら、この音を思い出してみてもいいね。」
- 任意の対話起点：「りんごは、そのままと切ったもの、どっちが食べやすい？」。嗜好に正誤・追加ptを付けない。
- 根拠：[Cambridge Dictionary「apple」](https://dictionary.cambridge.org/dictionary/english-japanese/apple)。例文は本仕様の独自原稿。

#### E02 blue／色

- 問題：「音を聞いてね。どの色かな？」。音声原稿：`blue`。
- 選択肢：A 青（あお）／B 赤（あか）／C 黄色（きいろ）。色の丸は補助で、文字だけでも選べる。
- 正解：A。
- 固定解説：「色を表す blue は、青のことだよ。」
- 日常の例：「青いえんぴつを見つけたら、blue の出番だね。」
- 任意の対話起点：「身近に青いものはある？」。カメラを要求しない。
- 根拠：[Cambridge Dictionary「blue」](https://dictionary.cambridge.org/dictionary/english-japanese/blue)。空が常に青いという説明はしない。

#### E03 bird／生き物

- 問題：「音を聞いてね。どの生き物かな？」。音声原稿：`bird`。
- 選択肢：A 犬（いぬ）／B 魚（さかな）／C 鳥（とり）。絵を付ける場合は一般的な鳥で、テーマ依存にしない。
- 正解：C。
- 固定解説：「bird は、鳥のことだよ。」
- 日常の例：「公園で鳥を見かけたら、bird ってことばを使えるね。」
- 任意の対話起点：「好きな鳥はいる？」
- 根拠：[Cambridge Dictionary「鳥」](https://dictionary.cambridge.org/dictionary/japanese-english/%E9%B3%A5)。すべての鳥が飛べるとは説明しない。

### ふしぎ：知りたくなる入口

#### F01 月の光／宇宙

- 問題：「夜、月が明るく見えるのは、どうしてかな？」
- 選択肢：A 月に大きな電球があるから／B 太陽の光をはね返しているから／C 月全体が燃えているから
- 正解：B。
- 固定解説：「月は太陽の光をはね返しているよ。その光が、地球にいるぼくたちの目にもとどくんだ。」
- 日常の例：「月を見かけたら、太陽の光がここまでとどいたんだな、と考えてみよう。」
- 任意の対話起点：「月を見たことはある？」。夜の外出を促したり、場所を尋ねたりしない。
- 根拠：[NASA「Moonlight」](https://science.nasa.gov/moon/moonlight/)。解説は独自の子ども向け要約。

#### F02 イルカの息／動物

- 問題：「イルカが息をするときに取り入れるのは、どれかな？」
- 選択肢：A 空気（くうき）／B 海の砂／C 海水（かいすい）
- 正解：A。
- 固定解説：「イルカは、ぼくたちと同じように空気で息をするよ。水面に出て、頭の上の穴から息をするんだ。」
- 日常の例：「映像でイルカが水面に出たら、息をする様子も見られるかもしれないね。」
- 任意の対話起点：「イルカの、どんなところが気になる？」。未確認の生態質問には推測で答えない。
- 根拠：[NOAA Ocean Today「Dolphin Anatomy」](https://oceantoday.noaa.gov/dolphinanatomy/)。息止め・潜水のまねは促さない。

#### F03 太陽の仲間／宇宙

- 問題：「太陽は、どの仲間かな？」
- 選択肢：A 地球のまわりを回る月の仲間／B 空に浮かぶ雲の仲間／C 自分で光を出す星の仲間
- 正解：C。
- 固定解説：「太陽は、自分で光を出す星なんだ。地球にいちばん近い星だよ。」
- 日常の例：「太陽も星。でも、直接じっと見てたしかめてはいけないよ。」
- 任意の対話起点：「宇宙のどんなことが気になる？」。観察を勧める場合も太陽の直視・望遠鏡での直視を促さない。
- 根拠：[NASA「Sun: Facts」](https://science.nasa.gov/sun/facts/)。惑星と恒星を同じ分類として説明しない。

## 7. 問題データと追加実装の境界

各問題の項目案：`id`、`version`、`genre`、`content_level`、`prompt`、`choices`（安定IDと本文）、`correct_choice_id`、`explanation`、`everyday_example`、`conversation_starter`、`reading_overrides`、`audio_ref`、`sources`、`review_status`、`reviewed_at`、`safety_note`。難易度はテーマと独立し、自動で学力を決め付けない。

問題はdraft→人による内容・読み・音声・安全性確認→publishedの順で公開する。更新時は版を変え、途中セットが参照する版を保持する。典拠の文章・画像・音声を丸ごと転載しない。誤答選択肢にも複数の正解が混ざらないことを確認する。

初回の家庭内試用はこの9問＝各ジャンル1セットでよい。毎日新問が出るとは約束しない。継続公開には各ジャンルの問題在庫を増やす必要があるが、まず試用してから作る。正誤の長期履歴や学力推定は不要。サーバーは進行・完了・加点と出題版に必要な最小限を持ち、途中セットは完了／破棄後に問題別応答を削除し、再送用の完了記録と台帳参照を残す。

### 既存APIだけでは完結しない

新機能には、セット開始・進捗保存／復元・固定の回答判定・完了と一日一回加点・回答後限定の会話のサーバー機能が必要。既存の `/api/status` へ架空の宿題を投げたり、テスト直し・親調整の口で加点を代用したりしない。APIパスは次の実装計画で確定し、既存APIの形は壊さず追加する。

子の認証・家庭所属をサーバーで検証する。クライアントから任意の子ID・正解フラグ・delta・日時を渡して加点できる方式にしない。進捗イベントは順序・セット所有者・問題IDを検証し、固定正解をサーバーが返す。正答率を報酬条件にしないことと、不正な台帳書込みを許すことは別。

確認したローカルの参照実装では、ポイントは `mimamori/points.py` と `mimamori/ledger.py`、ルートは `main.py`、相棒は `mimamori/kid_agent.py`。これは進行中のClaudeの最新作業を確認したものではない。UI改修完了後に最新コードを読み直す。台帳基盤が競合安全な一意制約／トランザクションと永続性を保証できない場合、参加加点を公開しない。

作業の切り分け候補は、A 問題データ・校閲、B 専用画面、C セッションと台帳連携、D 回答後のAPI対話。今はファイルの編集や担当割当を始めない。共有ファイル `main.py`・台帳等の所有者は実装計画で一人にまとめ、現UI改修との同時編集を避ける。

## 8. 受入チェックと次の順番

| チェック | 通過条件 |
|---|---|
| 正解・誤答・わからない | どの組合せでも3問と解説を終えれば同じ参加条件。正答率を報酬や人格評価に使わない |
| 配点未設定 | 勝手に1ptを付けない。開始前からポイントなしと分かる |
| 同日・複数端末・別ジャンル | 同じ子への加点は合計1回。並行完了・連打・再送でも台帳が二重にならない |
| 日またぎ | 未完了セットは完了日の枠。完了済みセットの再送は翌日も同じ結果 |
| 中断・再開・子切替 | 進捗と会話が混線せず、未送信を保存済みにしない |
| 解説と宿題の境界 | 回答後の固定解説は読める。写真の宿題や未回答問題をAIに解かせられない |
| 会話・障害 | 1セット2往復で打ち切り、回答・加点はAPI障害や予算上限から独立 |
| 読みやすさ | 小1／小6／中学生の設定、3テーマ、明暗、文字200%、音なしで操作可能 |
| 親の負担 | 未参加・誤答がboardに例外として出ない。毎日の承認や問題作成を親に求めない |
| 既存の目的 | クイズをしても宿題完了・週次目標・宿題台紙は増えない |

家庭での試用では「どれが好き？」「もう一度遊びたい？」「日常でこの言葉を使えそう？」を本人に聞く。学習効果が実証されたとは扱わない。滞在時間を伸ばすことや毎日全ジャンルを消化することを成功目標にしない。自発的に開いても、毎日の行動導線が見つけにくくなったら配置を見直す。

**次の順番：** この仕様と9問をユーザーがレビュー → 配点等を決め、子どもへの小さな試用で文言調整 → 現UI改修完了後に最新コードを確認 → 独立した実装計画を作成 → 承認後にClaudeへ渡す。今の段階では実装しない。

## 9. 今回は採らないもの

- 上の子の歴史・試験範囲・暗記カリキュラム：別の本格学習アプリの検討へ分ける。
- 全問正解ボーナス・発音採点・正答率ランキング：結果への報酬や兄弟比較になる。
- 宿題完了による解放、強制日課、連続ログイン、失敗で消える報酬：任意の好奇心を義務に変える。
- LLMが毎回問題と答えを生成し、そのまま出題：内容確認と難易度の統制が難しく、費用も増える。
- 自動音声会話、常時マイク、画像の都度生成：最初の価値の確認に不要。
- 親が毎日問題を登録する、理解を承認する：親の管理を増やす。
- 会話から子の能力を推定して固定ラベルを付ける、個人の好みを外部へ共有する：この機能の目的に不要。
