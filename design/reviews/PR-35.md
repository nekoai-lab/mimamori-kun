## 問題なし

### 1. 3秒で結論を読めるか

| 状態 | 判定 |
| --- | --- |
| 確認対象あり | 「確認すること N件」→理由の順で、今日見る必要があることを先に把握できる。カードも理由→誰→内容→期限→操作の順。期限超過は文とアイコンでも示し、色だけに頼らない。 |
| 新しい知らせのみ | 「新しい知らせがあります」＋「承認は不要です」で、子どもの登録を親の承認待ちへ戻していない。ごほうびの通知には専用の案内がある。 |
| 両方なし | 「いま確認することはありません」＋「登録済みの予定と新しい知らせを確認しました」で、確認した範囲を補足している。「抜けはありません」とは断言しない。 |
| 取得失敗 | 「確認できていない情報があります」＋取得できなかった対象＋再読込がある。タスク取得失敗なのに、取得できた空の通知だけで安心文を出していない。 |

提出のスマホ・PC画像に加え、実コード＋模擬APIの375×667では、4状態とも結論見出しの上端が約132pxにあり、初期表示で読めた。これは情報配置の評価であり、実際の親を対象にした3秒テストの測定結果ではない。

- 家庭全体の例外を数え、「すべての予定」の子フィルタとは分離している。上の子・下の子の例外がある状態で下の子へ絞っても、結論と例外は家庭全体の2件のまま。兄弟のポイントも表示していない。
- `pending`、期限切れの宿題・提出・持ち物、今日の提出・持ち物を例外にし、通常の今日の宿題と未来の予定は二階層目へ移している。done・rejectedを除外し、doingを完了と扱わない。コードと既存テストを確認した。
- 日付判定はサーバーの `today`・`days_left` を用いる。「すべての予定」に過去14日〜未来14日の取得範囲と未撮影の紙等が対象外であることを明記している。

### 2. 取得失敗・前回の情報

- 最初から予定を取れない場合は「予定: 未取得（最新を確認できません）」とし、取れた知らせの取得時刻と分けている。
- 一度取得した例外2件・通知1件を残したまま、予定と知らせの両方を500にすると「最新の状態を確認できません」へ切り替わった。前回の取得時刻を保持し、各情報へ「最新を確認できません」を添える。古い情報を最新として安心させない。
- 再読込成功で現在の結論へ回復した。前回情報の保持は同一ページ内のメモリであり、オフライン永続保存を保証するものではないが、画面もその約束をしていない。
- 取得途中は「確認しています」。片方が先に成功しても、もう片方を待つ実装になっている。D1は、この取得全体のエラー表示ではなく、カードを操作したときのエラーの位置の問題。

### 3. 対応済みと既読の区別

- タスクの「対応済みにする」と通知の実際のラベル「見た」は別の場所・別の操作になっている。「見た」という短い表記でも、通知の既読とタスク完了を混同させる構造にはなっていない。
- ブラウザで送信先と内容を確認した。対応済みは `/api/status` に対象の `event_id` と `status:done`、既読は `/api/notices/seen` に通知IDだけを送る。通知を見てもタスクの例外件数は変わらない。タスクを完了しても通知を勝手に既読にしない。
- 複数の通知を並べられる。「内容を確認」を開いた先に対象名付きの取消操作があり、コード上は対象名を含む確認ダイアログの後に送信する。成功結果が不明なときはカードを消さない。
- ごほうび通知は親の `/reward` への入口と「既読にしても申込の対応は完了しません」を備える。通知の既読だけで交換を承認しない。未解決申込全件の保証は現行APIではできないという仕様上の制約も、そのまま残る。

### 4. 二階層目へ移した操作

- 通常予定は「すべての予定を見る」の1操作で開き、子フィルタ・済表示・日付別一覧が残る。管理は「メニュー・追加・管理」と用途を明記している。日常の結論の前にこれらを置かない判断は適切。
- 手で足すフォームは展開時に件名へフォーカスが移る。入力→模擬登録成功→「入れました」まで確認した。まいにちのことと年間予定もメニュー内から開き、子の選択欄へ到達できた。サーバー側の登録機能全体を再検証したものではない。
- ログアウトは管理を開くまで通常表示されない。既存の全端末確認と失敗文・再試行可能状態を保つコードになっている。今回、実際のログアウトは行っていない。
- 通常表示は320px・375px・PC 1440pxで横にはみ出さないことを確認。暗い画面・文字2倍も提出画像で結論を判別できる。文字2倍の画像は画面上部のみなので、全操作の拡大受入を完了したとは判断しない。

### 5. 学年・ふりがなのフォーム

- 「設定の保存はまだ利用できません」「表示例を試すフォーム」「保存済みの設定ではありません」をフォームより前に置き、保存ボタンも理由付きで無効になっている。試すことと保存を明確に分けている。
- 子ども・学年・漢字を使う範囲・ふりがなにラベルがある。小3・前学年までを選ぶと表示例のルビが減り、別の子を選ぶと未設定へ戻ることをブラウザで確認した。下の子で試した値を上の子の保存済み設定のようには見せない。
- 学年を4月に自動変更しないことも明記。テーマの年齢イメージと、学年に応じた漢字・ふりがなの設定を混同していない。
