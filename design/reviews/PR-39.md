# UXレビュー：PR #39 子ごとの設定の保存

- 対象：`feat/24-settings` / `72c1a0092ad873964a5e7b3f5137a158dfa84c0a`
- 範囲：見た目の保存、相棒の名前の保存、親の学年・ふりがなの保存の3場面だけ。
- 子どもが変更できる項目と、親だけが変更できる項目の決定は維持する。ほかの画面・機能は再判定しない。

## 直すもの

### F1［中］保存後に編集すると、未保存の値のそばに「保存しました／おぼえたよ」が残る

**場所：** `static/board.html:532` のフォーム変更処理、`static/kid.html:428` の名前プレビュー処理。

**再現（実ブラウザ・375×667、実際のHTML/JSと模擬API）：**

1. 親の学年を小2として保存し、「「下の子」の学年・ふりがなを保存しました。」を確認。
2. 小3に変更して表示例を見る。「保存する」は押さない。
3. POSTは増えず保存先は小2のままだが、小3のフォームの下に成功文言が残る。
4. 相棒名でも、保存成功後に入力を別の名前へ変えると、未確定の新しい名前の下に「このなまえを おぼえたよ」が残る。

**困ること：** 表示例だけでは保存しない仕様なのに、今表示している値を保存できたと読める。親は変更を保存せず閉じ、子どもは再読込で名前が戻ったように感じる。単なる見た目の持ち越しではなく、今回の「覚えたことが伝わるか」に関わる。

**原因：** 親の変更処理は `previewReading()` だけ、名前の入力処理は `previewName()` だけを呼び、直前の成功状態を更新しない。保存先が消える問題ではない。

**直し方：** 保存成功の表示を、保存した値に対応させる。値を変更したら成功文言を解除し、例えば次の案内に置き換える。自動保存には変えない。

| 場面 | 変更後の案内例 |
|---|---|
| 親が保存後に学年・漢字の範囲・ふりがなを変更 | まだ保存していません。「保存する」で確定します。 |
| 子どもが保存後に名前を編集／既定名へ戻す | まだ おぼえていないよ。「このなまえにする」を おしてね。 |

**修正後の完了条件：**

- 親の3項目と相棒名で「保存成功 → 値を変更」のあと、新しい値に対する成功表示が残らない。
- 編集だけではPOSTしない。保存ボタンを押して成功したときだけ成功表示になる。
- 保存失敗は再試行の案内になり、再試行成功で成功表示になる。
- 名前の保存待ちに入力を変えた場合も、先に送った名前の成功応答を、現在の未保存の名前の成功として表示しない。
- 子の切替時は、その子の保存済みの値と状態を表示する。テーマや別の設定を消さない。

## 持ち越し

- `/board` の「保存する」の標準ボタンの見た目。操作名と成功・失敗の結果は判別できるので、このPRの直すものには数えない。共通の親のボタンへの統一は見た目の調整時に行う。
- `f-kid-name-saved-375-sp.png` は成功文言が画像の下に出ており、画像単独では保存成功を確認できない。ブラウザではシート内をスクロールして結果欄まで到達できた。再撮影時は結果文言を含めると、レビュー資料として分かりやすい（操作不能の指摘ではない）。

## 問題なし

### 1. 見た目の保存

- 「このみためを おぼえたよ」は、画面だけの変更ではなく保存が終わったことを短く伝える。320px・375px・PCの提供画像で確認できる。
- 実ブラウザで、選択シートからモノクロを選択し「これにする」→成功文言→再読込して同じテーマが復元される流れを確認した（保存先は模擬API）。
- APIは保存失敗を成功として返さず、既存の保存アダプタも非成功応答をエラー扱いにする。失敗時に成功文言へ進む実装ではない。

### 2. 相棒の名前の保存

- 「このなまえを おぼえたよ」は成功を伝えられる。500応答では「この画面では変えたけれど、まだ覚えられていないよ。もういちど『このなまえにする』で ためしてね」となり、次に押す操作が具体的。失敗→再試行→成功を実ブラウザで確認した。
- 名前だけ、テーマだけの部分更新を送り、サーバーも送られた項目だけを更新する。名前保存でテーマを消さず、その逆も維持する実装とテストを確認。ブラウザの模擬APIでも両方向を確認した。
- 名前の変更は相棒の呼び名に反映される。相棒の態度や権限を変更する提案は不要。

### 3. 親の学年・ふりがなの保存

- 保存成功には対象の子が明示される。失敗は通信の確認と「保存する」の再操作を案内し、入力値を保ったまま再試行できた。
- 子の切替で保存済みの値を読み込み直す。実ブラウザで下の子から上の子へ切り替え、上の子の保存済み学年に変わることを確認した。
- 読込失敗時は「子どもを選び直すか、再読込してください」と案内し、保存を無効にする。分からない値で上書きさせない点は妥当。
- 子切替前の遅い応答を反映しない世代番号の処理をコードで確認した。

- `main.py`、`mimamori/appearance.py`、`tests/ux/test_appearance_api.py`、関連画面の実装とテストを参照。部分更新、子ごとの分離、権限、保存先を開き直すテストがあることを確認した。
- 実ストレージの再起動・別端末復元はPRの実装側記録とテスト定義を参照したもので、今回こちらで本番Firestoreや実バックエンドを再実行した結果ではない。pytest一式も再実行していない。390px・文字200%・横向きの全レイアウト再検証は今回実施していない。

## 対応（Claude Code、F1）

- **/board の学年・ふりがな**：保存済みの値を覚えておき、フォームの値がそれと違うあいだは「まだ保存していません。「保存する」で確定します。」を出す。元の値に戻すと消える。保存の返事が届いたとき、送った値とフォームの値が違えば成功ではなく未保存の案内を出す。選ぶだけでは送らない。
- **/kid の相棒の名前**：覚えた名前と入力が違うあいだは「まだ おぼえていないよ。「このなまえにする」を おしてね。」を出す（「まる にもどす」で変わった場合も同じ）。保存待ちのあいだに入力を変えたときは、先に送った名前の成功を今の名前の成功として出さない。子を切り替えたら、その子の覚えた名前を基準にする。
- 失敗 → 再試行 → 成功で成功表示になる流れは前のまま（テストも前のまま通る）。
- テスト：`tests/ux/test_board.py::test_reading_settings_load_for_the_child_and_save_only_on_submit` に「保存 → 変える → 未保存の案内、戻すと消える、送信は1回」を足し、`tests/ux/test_kid.py::test_name_success_is_not_shown_for_an_unsaved_name` を足した。修正を外すと両方落ちることを確かめた。全体 517 件が通る。
- ブラウザ（ローカルの JSON 台帳）：/board と /kid で「保存 → 値を変える → 未保存の案内 → 元に戻すと消える、POST は1回」を 375px・320px・320px 文字200%・375px ダーク・PC で確かめた。/kid はテーマ（しろい小鳥）あり。横スクロールなし、ページのエラーなし。
- 撮り直し：`design/screenshots/f1-board-unsaved-*.png`、`f1-kid-name-unsaved-*.png`（各5枚）。持ち越しの指摘どおり、結果の文が写るように撮った。
