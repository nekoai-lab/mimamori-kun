# PR #67 UXレビュー

対象：`perf/62-single-call`、`99b11cec21f13f7155747b200dcf2b66a6cce55f`。子・親の読み取り待機、結果、追加、一時的な失敗を確認。仕様は `design/UX_SPEC.md` §2.2 と今回の依頼を基準にした。ほかのPRの判定は変更しない。

## 直すもの

### S62-1（中）：一時的な失敗の直下が「とりなおす」で、写真の再撮影が必要に見える

- 対象：`s62-timeout-parent-375-sp.png`、`s62-timeout-kid-375-sp.png`、`s62-429-kid-375-sp.png`。実装：`static/index.html` の `readFailure`（407〜412行）、`controls`。
- 説明文は、親では混雑、子では一時的に読めない状況を伝えており、写真を責めていない。しかし、その直下の操作は「とりなおす」「手でいれる」。ブラウザでも「とりなおす」はファイル選択を開き、同じ写真の再試行ではなかった。上に戻れば「読み取る」で再送できるが、失敗の案内からは分からない。
- 直し方：一時的な失敗では、同じ写真を保持して読み取りを再試行するボタンを結果欄に置く。子は「もういちど よむ」、親は「もう一度読み取る」など。「写真は そのままで いいよ」／「写真を撮り直す必要はありません」を添え、撮り直し・手入力は補助操作にする。写真自体が読めない場合の案内とは分ける。
- 完了条件：timeout・429の子／親いずれも、案内の近くから写真を選び直さず再試行できる。待機中の連打は送信を増やさず、再失敗でも同じ導線が残る。320px・文字200%でも説明とボタンに到達できる。

### S62-2（中）：再撮影で「既に入っていた予定」と「日付の確認待ち」が混ざると、前者の結果が消える

- 対象：`s62-kid-done-320-text200-sp.png`、`s62-kid-done-375-dark-sp.png`。実装：`static/index.html` の `emptyResult`（567行付近）。
- 依頼では同じプリントをもう一度撮った状態だが、画像には「日付は おうちの人に きいてもらうね」「日付の確認を待っています」だけが出る。既に入っている予定をどう扱ったかが分からず、プリント全体が未登録で待っているようにも読める。
- ブラウザで `items:[]、skipped:4、date_questions_count:1` を表示すると再現する。`date_questions_count` がある場合に `skipped` の表示を選ばない三項分岐が原因。確認待ちが0件なら「もう入っていたよ」は出る。
- 直し方：重複の結果と日付確認の結果を排他的にしない。例：「やることは もう入っていたよ。ふやしていないよ」＋別の短い案内「日付が わからないものは おうちの人に きいてもらうね」。実際に既登録だったものだけに言及し、プリント全部が登録済みとは言わない。「きょうを みる」を残す。
- 完了条件：重複のみ／日付確認待ちのみ／両方の3状態を区別できる。両方では「重ねて登録していない」と「日付確認は親へ」が同時に伝わる。新規登録時の「やることに 入ったよ」と混同しない。件数を相棒の台詞で数える必要はない。

## 持ち越し

- 原本の拡大は実装されているが、スマホの見た目は「撮ったもの」と小さな原本だけで、タップによる拡大が分かりにくい。今後「タップで大きく見る」などの視覚的な手掛かりを検討する。今回は原本を結果と一緒に残し、拡大可能にする点は満たしているため、直す件数には含めない。
- 中央値約7秒という性能値、実サービスのtimeout／429発生条件、実機の読み上げ品質は今回再計測していない。文字200%・ダークは提供画像の評価で、全端末・全操作の実機保証ではない。
- 日付を親に確認する機能そのもの、既存の候補編集フォーム全体、共通ナビの別PRの指摘は対象外。

## 問題なし

- 待機の「読んでいます／よんでいるよ」から「もうすぐです／もうすぐ」への変化は短く、段階を理解できる。読めた項目がリストに増えることで処理が進んでいることも見える。実装では途中結果をそのまま登録確定にせず、最終結果に切り替えている。
- ブラウザでダミーのストリームを段階的に流し、子・親それぞれの文言と1件の追加表示、最終結果への遷移を確認した。待機文は `role=status` / `aria-live=polite`。実際のスクリーンリーダーによる発話確認は未実施。
- 親の原本はPCで候補の左、スマホで候補の上に残る。候補との照合に戻れる配置。320px・文字200%の画像でも原本が候補を横へ押し出していない。ダークでも原本自体を暗く加工せず残している。
- 「ほかにも ある？」と「＋ついか」は候補一覧の末尾でまとまり、読み取り漏れを補う入口として見つけられる。文字200%では縦に折り返して表示される。ダミー候補を使ったブラウザ確認では、押すと手入力欄が開き、「やること」の入力にフォーカスが移った。
- 新規登録の子の結果は「やることに 入ったよ」＋項目一覧＋「きょうを みる」で次に進める。重複のみの場合の「もう入っていたよ」も適切。ただし、日付確認待ちと混ざる場合はS62-2。
- 提供された375px・320px・文字200%・ダーク・PCの代表画像で、今回追加した待機文・追加ボタン・結果文の極端な1文字折返しや横切れは見られない。320pxのブラウザ確認でも確認した結果状態のページ幅は320px内だった。

## 確認方法と限界

- 提供画像の目視、HTML/CSS/JavaScriptの照合、Chromium＋PlaywrightによるダミーAPIで確認。実際の画像読取サービスやカレンダーへ送信・登録していない。
- エラーと混在結果は実ページの表示関数でも条件を分けて再現し、エラーの「とりなおす」がファイル選択を開くことを確認した。追加フォームは候補データを設定して検証した。
- 本レビューは表示・導線の評価であり、Geminiの抽出精度や速度を合格判定するものではない。
- 公開用の本文に実名・学校名は記載していない。変更するファイルは本ファイルだけとし、`tasks/current.md` は変更しない。
