最終更新: 2026-09-30 ／ 旧設計: 2026-09-13・`要件定義書.md` v1.2

**現行の画面・導線・見た目の正本は [design/UX_SPEC.md](../design/UX_SPEC.md)。**
この文書は旧設計の意図を残し、変わった節から正本へ案内する。図や台詞は現行画面そのものではない。
ログイン（#17）・日付の確認待ち（#65）・読み取りの段階表示（#67）は後から加わったため、以下に補足する。

## 0. 画面設計の方針（3つだけ）

**① 初回に見えるのは「今日やること3〜5個」だけ**
グラフ・統計・全体像は必ず2階層目に置く。続かない最大の理由は作り込みすぎ。
**ゲーム性は演出に置き、構造には置かない。**

**② 完了は1タップ、編集は数クリック**
「数クリックで直せるから、1日できなくても投げ出さずに済む」——**リカバリのしやすさ＝継続率。**

**③ 確認画面を新設せず、普段の入力フォームをAIが埋めた状態で出す**
新しい確認UIを覚えさせないこと自体が省力化になる。

## 3. `/` 撮る

### 3.1 撮影

**UX_SPEC.md §2.2** を見る。ファイル選択で写真を渡し、手入力も選べる。
#67 では長辺1600pxに縮め、写真を横に並べて「＋ついか」で足す。
読み取り中は段階と先に読めた件を出す。通常1回のストリーミング生成、全体25秒。

### 3.2 候補確認 ← ここが体験の急所

現行は **UX_SPEC.md §2.2** を見る。以下は親の確認画面の旧案。子が撮った確定日付の予定はそのまま登録し、親に知らせる。

```
┌──────────────────────────────┐
│ [原本サムネイル] ←タップで拡大   │  ① 根拠を横に置く
├──────────────────────────────┤
│ ☑ 運動会                      │
│   9/27(土) ・ 下の子 ・ 行事    │
│   [下の子 ▾] ←推定値。1タップで変更│
├──────────────────────────────┤
│ ☐ 遠足  【重複】               │  ② 重複は最初から外す
│   10/3(金) ・ 既に登録あり      │
├──────────────────────────────┤
│ ☑ 個人面談  【日程変更】        │  ③ 旧→新を並べる
│   9/20(土) → 9/27(土)          │
├──────────────────────────────┤
│      [ まとめて登録（2件） ]    │
└──────────────────────────────┘
```

- **原本サムネイルを必ず上に置く**（FR-1.6）
- 「どの子か」は**推定値をデフォルト表示**し、1タップで変更（FR-2.2）
- **完全一致は候補に出さない**（D-33）。並ぶのは 新規・追記・日程変更 の3種だけ
- 登録後トースト：**「2件を登録しました ／ 取り消す」**（一括アンドゥ・10分）

### 3.3 読めなかったとき・日付の確認待ち

基本は **UX_SPEC.md §2.2 の状態と文言** を見る。#67 で一時的な失敗と写真の読み取り失敗を分け、
一時的な失敗には写真を残して「もう一度読み取る」を出す。手入力へも進める。範囲指定のなぞり直しは未実装（WBS D-8）。

#65 で増えた状態：日付・曜日の食い違いなどは推測せず、「何月何日？」と親に聞く。
親は撮る画面または `/board` の「確認すること」で日付を選び、登録／あとで／取り下げを選ぶ。
子にはおうちの人へ確認中と伝え、今日のやることにはまだ出さない。
3日後以降の確認時に1回だけ知らせ直す。同じ質問はまとめ、回答時に予定が既にあれば「もう入っていたよ」と伝える（#70〜#74）。

### 3.4 手入力モード（目標：10タップ・20秒）→ **実装済み・実測6タップ（09-13）**

```
教科  [国語][数学][英語][社会][理科][その他]   ← 1タップ
だれ  [上の子][下の子]                          ← 1タップ
いつ  [今日][明日][あさって][日付を選ぶ]        ← 1タップ
やること  ________________________              ← ここだけ入力（空でもOK）
          [ 昨日と同じ ]
                              [ 追加する ]
```

**実装（09-13）**: 並びは **だれ → きょうか → いつ → なに → やること**。
教科は子で入れ替わる（小学生＝ひらがな／中学生＝漢字）ので、だれを先に置く。
「昨日と同じ」は昨日の宿題・持ち物を今日ぶんに写す（既にあるものは作らない）。
読み取りに失敗した画面からも、そのまま手入力に落ちられる。

現行は **UX_SPEC.md §2.3・§3.7** を見る。以下は旧案。今は「きょう がんばった」と交換に使える残高を分け、完了・空・取得失敗も区別する（#28・#51）。

```
┌──────────────────────────────┐
│   (相棒キャラ) 「きたね！算数からいく？」│
├──────────────────────────────┤
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ │
│  │算数 │ │国語 │ │英語 │ │うわ │ │  ← アイコン＋一言
│  │ ○  │ │ ○  │ │    │ │ばき │ │     タップで完了
│  └────┘ └────┘ └────┘ └────┘ │
├──────────────────────────────┤
│  こんしゅう  ★★★☆☆            │  ← 週の台紙（★5つ）
│  ポイント 24                   │
├──────────────────────────────┤
```

## 10. 相棒の台詞（「げんき」タイプ）

**現行の台詞・会話の戻し方は UX_SPEC.md §3.6 を見る。** 以下は09-13の記録で、「2往復で必ず戻す」などの旧案を含む。おやすみ券の台詞は未実装。

子ども2人に3タイプを見せて選ばせた結果、**「げんき」タイプ**を採用（2026-09-13）。
ただし `kid_agent.py` に実装済みの**態度ルールが優先**する。元気さは口調で出し、内容はルールに従う。

### 10.1 態度ルール（実装準拠・変更しない）

- **答えを言わない。** ヒントは「場所」と「やり方」まで
- **残りではなく、済んだ数を数える。** 「あと3つ」ではなく「**1つ終わったね**」
  - 数を聞かれたら黙って話を変えず、「数は数えないことにしてる」と一度だけ言って次の1つを示す
- **評価しない。** 「えらい」「すごい」ではなく「**終わったね**」
- **責めない。** 期限を過ぎていても「まだ残ってる。今日やっちゃう？」
- **質問は1つずつ。同じことは2回まで**（3回目は引く）
- **前と同じ文を返さない**
- **秘密を持たない。** 親も見られることを画面に常時表示

### 10.2 台詞表（ルール準拠）

| 場面 | 台詞 |
|---|---|
| ひらいたとき | きたね！算数からいく？ |
| 1つ終わった | やったね！1つおわった！ |
| ぜんぶ終わった | ぜんぶおわった！ |
| 夕方まだ残ってる | まだのこってる！いまやっちゃう？ |
| できなかった日 | きょうはここまで！あしたにまわしとくね |
| おやすみ券が出た | おやすみ券つかっといた！ |
| 撮ってほしい | プリントあった？とっちゃお！ |
| 7日つづいた | 7日つづいた！ |
| 数を聞かれた | 数は数えないことにしてるんだ。つぎはこれ！ |

**上の子だけに出る場面**

| 場面 | 台詞 |
|---|---|
| 入らない警告 | このままだと社会が2日たりない！どれ削る？ |
| 計画を変えた | オッケー！金曜が110分になった！ |
| 雑談から戻す | わかる！……で、のこりの25分いける？ |

### 10.3 トーンの切り替え（1箇所だけ）

**できなかった日はテンションを一段落とす。** 「あしたにまわしとくね」までは元気でよいが、
そこから先の励ましを足さない。

### 10.4 聞くことの3層（実装準拠）

1. **今日のもの**（期限が今日以前）— 「宿題終わった？」
2. **明日の持ち物**（明日の bring / event）— 「明日の忘れ物ない？」
3. **先回り**（3〜7日先の行事・テスト・提出）— 「週末◯◯だけど、進んでる？」

**3つ目が伴走の核。** 言われなくても自分で気づいて聞く。ただし**1回の会話で1つだけ**。

### 10.5 会話の置き場所

**下部の吹き出し**。タップで会話が開き、閉じると今日やることに戻る。
現行の雑談と戻し方は **UX_SPEC.md §3.6.3** を見る。短い雑談を受け止め、2往復だけを理由に機械的に切らない。

## 12. この設計で決めたこと（09-13 の履歴）

現行の導線・文言は冒頭の UX_SPEC.md と各節の補足を優先する。

1. 候補確認画面に**原本サムネイルを常設**する
2. 完全一致は候補に出さない。並ぶのは**新規・追記・日程変更の3種だけ**
3. 手入力は**タイトル1行以外すべてボタン**
4. 下の子は**アイコン＋台紙**、上の子は**量＋枠バー**で、同じ `/kid` を作り分ける
5. 「入らない」警告は**出るときだけ**最上部に。常設しない
6. `/board` の1画面目は**例外だけ**。空が正常
7. `/plan` は `/kid` の2階層目に置き、初回では見せない
8. **相棒は「げんき」タイプ**。ただし**実装済みの態度ルールが優先**
9. **台紙は週ごと（★5つ・日曜リセット）**
10. **会話は下部の吹き出し**。独立タブにしない
11. **日付の移動は「明日に送る」ボタンだけ**
12. **スタンプは3種類**。評価を禁じるのは相棒であって、親ではない
13. **承認前（pending）は子どもに出さない**
14. 完了した予定は消さず、**件名に ✓ を付けて一覧から外す**
