# デプロイ手順

Webhook・合言葉は人（Naomi）が入力する。Claude・Codex は秘密の値を見ない・聞かない。
この手順のクラウド操作と合言葉設定は、Naomi が AI と共有しない端末で実行する。
画面・ログ・履歴・リポジトリに Webhook や合言葉を残さない。端末の録画や `set -x` は使わない。
README の旧デプロイ案内より、この手順の順番を優先する。

## 準備

リポジトリ直下で、Naomi が `.env` を用意する（コミットしない）。
`GOOGLE_CLOUD_PROJECT`・`GOOGLE_CLOUD_LOCATION`・`MIMAMORI_CALENDAR_ID`・
`MIMAMORI_CHILDREN`・`MIMAMORI_MODEL` と必要なリマインダー設定を入力する。
`REGION` を指定する場合は `GOOGLE_CLOUD_LOCATION` と整合させる。
`SA_NAME`・`SECRET_NAME`・`SERVICE` はスクリプトの既定を使える。
変更するなら `.env` に指定し、準備とデプロイで同じ設定を使う。
Webhook と合言葉は `.env` に入れない。対象はみまもりくん専用プロジェクトとする。

```bash
set +x
set -a
source .env
set +a
export PROJECT="${GOOGLE_CLOUD_PROJECT:?}"
export REGION="${REGION:-${GOOGLE_CLOUD_LOCATION:?}}"
```

以後は同じ端末を使う。サービス名・Secret 名・SA 名は秘密ではない。
既定のままなら次を実行する（ロールバックでも必要）。変えた場合はその名前を指定する。

```bash
export SERVICE=mimamorikun SECRET_NAME=mimamori-notify-webhook SA_NAME=mimamori-run
```

課金と gcloud のログイン、実行者の API 有効化・SA/IAM 管理・Firestore 作成・
Secret 管理・Cloud Run のソースデプロイに必要な権限を事前に用意する。
Cloud Build のビルド用 SA にもソースビルドに必要な権限が必要（実行用 SA とは別）。
既定プロジェクトを書き換えず、各コマンドで `$PROJECT` を指定する。

## ① サービスアカウントの作成とカレンダー共有

```bash
bash scripts/setup_service_account.sh
```

必要な API（Secret Manager を含む）、実行用 SA、`roles/aiplatform.user`・
`roles/datastore.user`、Firestore の `(default)` データベースを準備する。
データベースがなければ `$REGION` に作るので、実行前に保存場所を決める。
失敗したら API・実行者の権限を確認し、この工程を完了してから進む。

最後に表示される「カレンダーの共有に追加するアドレス」を、Google カレンダーの
対象カレンダーの設定 →「特定のユーザーやグループとの共有」に
**予定の変更権限**で追加する。デプロイ前に完了させる。
アドレスは人が実行した画面だけで確認し、ファイルや PR に転記しない。

## ② Webhook を Secret Manager に入れる

```bash
bash scripts/put_secret.sh
```

Naomi が端末で Webhook を入力する。`read -s` で非表示入力し、
標準入力から `gcloud secrets versions add --data-file=-` に渡す。
値を引数・環境変数・一時ファイルに入れない。
Secret がなければ作成し、実行用 SA に Secret 単位の
`roles/secretmanager.secretAccessor` を付ける。再実行すると新しいバージョンを追加する。
デプロイでは `$SECRET_NAME:latest` を `MIMAMORI_NOTIFY_WEBHOOK` として参照する。

## ③ 合言葉3つを本番の台帳へ設定

**①で Firestore を作成した後なら、デプロイ前に設定できる。初回公開前に3人とも設定する。**
[README「4. 合言葉を決める」](../README.md#4-合言葉を決める)と
`tools/set_passcode.py` を参照する。依存関係の入った `.venv` を使う。
Naomi の ADC と、対象 Firestore へ読み書きできる権限が必要。
実行用 SA の権限を付けただけでは、Naomi の ADC に権限は付かない。

```bash
gcloud auth application-default login --project "$PROJECT"
MIMAMORI_LEDGER=firestore GOOGLE_CLOUD_PROJECT="$PROJECT" .venv/bin/python tools/set_passcode.py おうちの人
MIMAMORI_LEDGER=firestore GOOGLE_CLOUD_PROJECT="$PROJECT" .venv/bin/python tools/set_passcode.py 上の子
MIMAMORI_LEDGER=firestore GOOGLE_CLOUD_PROJECT="$PROJECT" .venv/bin/python tools/set_passcode.py 下の子
```

子の呼び名を変えた場合は `MIMAMORI_CHILDREN` に合わせる。
各回の表示が `台帳: firestore` であることを確認する。
合言葉は `getpass` で2回、非表示入力する。保存するのはハッシュだけ。
コマンドに合言葉を書かない。ローカル JSON に設定しても本番には反映されない。

## ④ デプロイ

公開前にスマホ・PCでログイン・撮る・親の一覧・子の今日・ごほうびを通し確認する。
公開リポジトリの資料・画像・履歴に実名・学校名・実物のプリントがないことも確認する。

```bash
bash scripts/check_deploy_ready.sh
gcloud meta list-files-for-upload --project "$PROJECT"
```

チェックが指摘0件（exit 0）であること、アップロードに `.git`・docs・samples・design・tests・
`.env*`・scratchpad 類・tools・scripts・`.claude` がないことを確認する。
`__pycache__/`・`*.pyc`・`.DS_Store` は `.gcloudignore` で除外する。
必要ファイルを追加した場合は `.gcloudignore` の個別許可も更新する。

Naomi が実行する：

```bash
bash deploy.sh
```

SA・Secret・最新バージョン・Firestore を確認できなければ停止する。
存在確認の失敗には権限不足も含まれる。案内された準備スクリプトと実行者の権限を確認する。
カレンダー共有や合言葉の設定は自動確認しないので①〜③を省略しない。
成功時に表示される URL で⑤を行う。

## ⑤ デプロイ直後の確認

本番でそれぞれ1回確認する。個人情報のないダミーのプリントを使う。

- 見た目・相棒の名前・学年が、再読込と別の端末でも残る（Firestore）。
- プリントを読み取れる（Vertex AI 経由の Gemini）。
- カレンダーへ登録できる。
- Slack の通知先に通知が届く。
- 子どものログインで親専用画面（`/board` など）と親専用 API に入れない（403）。
- 問題が出たら⑥へ。すべて通った後に WBS の A-1 を完了にする（実環境確認前には付けない）。

## ⑥ 戻し方・初回の公開停止

2回目以降は、直前に正常だったリビジョンを確認して切り替える。

```bash
gcloud run revisions list --service "$SERVICE" --project "$PROJECT" --region "$REGION"
read -r -p '戻すリビジョン名: ' PREVIOUS_REVISION
gcloud run services update-traffic "$SERVICE" --to-revisions "${PREVIOUS_REVISION}=100" \
  --project "$PROJECT" --region "$REGION"
```

切り替え後に⑤を確認する。トラフィックを戻しても Firestore・カレンダー・Secret の内容は戻らない。
Secret の `latest` も過去の値に固定されないので、通知設定の障害には別途対処が必要。

**初回は戻す先がない。匿名公開を止める。** この deploy.sh の
`--allow-unauthenticated` が付けた `allUsers` の呼び出し権限を外す。
IAM チェックが別途無効にされていた場合にも備え、有効にする。

```bash
gcloud run services update "$SERVICE" --invoker-iam-check \
  --project "$PROJECT" --region "$REGION"
gcloud run services remove-iam-policy-binding "$SERVICE" \
  --member=allUsers --role=roles/run.invoker \
  --project "$PROJECT" --region "$REGION"
```

Google にログインしていない別のブラウザから URL を開き、アプリへアクセスできないことを確認する。
これは匿名公開の停止で、IAM で許可された呼び出しや保存済みデータは残る。
`deploy.sh` を再実行すると匿名公開を再び許可するため、修正・確認を済ませてから実行する。

コマンドの根拠：Google Cloud 公式の
[公開アクセスと Invoker IAM チェック](https://docs.cloud.google.com/run/docs/authenticating/public)、
[IAM バインディングの削除](https://docs.cloud.google.com/sdk/gcloud/reference/run/services/remove-iam-policy-binding)。
